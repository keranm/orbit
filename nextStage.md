# Next Stage: Add SPM Dependency + Build

This stage must be done after PR [#634](https://github.com/Mesh-LLM/mesh-llm/pull/634) merges to `main` and a tagged release (≥ v0.66.0) is available.

## Prerequisites

- PR #634 merged to `main` on mesh-llm repo
- Tagged release ≥ v0.66.0 published
- Confirm the SDK product is named `MeshLLM` (not `MeshLLMFFI` or similar)

---

## Instructions

### 1. Add SPM dependency to `project.pbxproj`

The project uses `fileSystemSynchronizedGroups` (no explicit file references) but SPM packages still need to be declared.

**a) Add an `XCRemoteSwiftPackageReference` section** (insert before `/* End PBXProject section */` around line 200):

```
/* Begin XCRemoteSwiftPackageReference section */
		XXXXXXXXXXXX /* MeshLLM */ = {
			isa = XCRemoteSwiftPackageReference;
			repositoryURL = "https://github.com/Mesh-LLM/mesh-llm";
			requirement = {
				kind = upToNextMajorVersion;
				minimumVersion = 0.66.0;
			};
		};
/* End XCRemoteSwiftPackageReference section */
```

**b) Add an `XCSwiftPackageProductDependency` section** (after the package reference):

```
/* Begin XCSwiftPackageProductDependency section */
		YYYYYYYYYYYY /* MeshLLM */ = {
			isa = XCSwiftPackageProductDependency;
			package = XXXXXXXXXXXX; /* reference from above */
			productName = MeshLLM;
		};
/* End XCSwiftPackageProductDependency section */
```

**c) Add the product to the `orbit` target's `packageProductDependencies`** (line 114-115):

```diff
 			packageProductDependencies = (
+				YYYYYYYYYYYY /* MeshLLM */,
 			);
```

### 2. Add the SDK package resolver to `Package.resolved`

Run the project once in Xcode so SPM resolves the dependency automatically, OR manually add an entry to `orbit.xcworkspace/xcshareddata/swiftpm/Package.resolved`.

### 3. Build and fix compilation errors

The SDK API was stubbed against PR #634 branch — the release API may differ. Likely mismatches:

**`ChatService.swift`** (`orbit/Services/ChatService.swift`):
- `ChatRequest` initializer: `ChatRequest(model:, messages:)` — confirm signature matches
- `ChatEvent` enum cases: `node.inference.chat(request)` yields events — confirm `.tokenDelta(_, let delta)` and `.completed` and `.failed` still exist
- `ChatMessage` initializer: `ChatMessage(role:, content:)` — confirm signature

**`RuntimeAdapter.swift`** (`orbit/Services/RuntimeAdapter.swift`):
- `Node` initializer: `Node(inviteToken:, ownerKeypairBytesHex:, servingEnabled:)` — confirm
- `node.start()` — confirm it's async
- `node.stop()` — confirm
- `node.serving.load(ref, options:)` → returns `LoadModelResponse` with `.modelId` — confirm
- `node.models.download(ref)` — confirm
- `node.models.delete(ref, options:)` — `DeleteModelOptions(removeFiles:, removeCache:)` — confirm
- `node.models.installed()` — confirm return type has `.name`, `.id`, `.formattedSize`
- `node.models.recommended()` — confirm return type has `.name`, `.id`, `.description`, `.formattedSize`
- `node.inference.listModels()` — confirm return type has `.id`, `.name`
- `Node.connectPublic(ownerKeypairBytesHex:, query:)` — confirm
- `Node.discoverPublicMeshes(_ query:)` — confirm return type fields
- `PublicMeshQuery(model:, minVramGb:, region:, targetName:, relays:)` — confirm
- `InviteToken(_:)` — confirm exists
- `node.status()` — confirm `.connected`, `.peerCount` fields

**Domain files** that may need updating:
- `Domain/MeshModels.swift` — `MeshConnectionState`, `MeshModelEntry`, `DiscoveredMesh` are still Orbit-domain types. They may be replaceable with SDK types now (the plan calls for this), but the minimum viable change is to keep them and just fix any compilation errors in the adapter code that maps between SDK and domain types.

### 4. Verify key paths

- **Mesh**: `joinPrivateMesh()`, `joinPublicMesh()`, `leaveMesh()`, `discoverPublicMeshes()`
